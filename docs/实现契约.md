## 2. 生成代码契约

### 2.1 `types/rrc_types.h`（伞头 + 分块 part）

`rrc_types.h` 只做 include 汇总；声明按下列顺序拆分到 `rrc_types_partNNN.h`。
每个 part 文件包含它之前的 part（保证单独打开时也能解析依赖），单文件目标
≤240 KB（CLion/ReSharper 默认分析阈值 300 KB、PSI 阈值 2 MB；实测单文件
6.2 MB 会导致分析暂停且 Go to Declaration 失效，故按方案 Q-10 拆分为 B 方案）。

声明顺序（全部在 `extern "C"` 内）：

1. 基础类型：
   ```c
   typedef struct BitString  { uint8_t* bytes; uint32_t bitLength; } BitString;
   typedef struct OctetString{ uint8_t* bytes; uint32_t length;    } OctetString;
   typedef struct Null       { uint8_t _dummy; } Null;
   ```
2. 所有结构体前向声明：`typedef struct <Name> <Name>;`
3. 枚举定义：
   - 不可扩展：`typedef enum <Name> { <Name>_<值名> = <序号>, ... } <Name>;`
   - 可扩展：`typedef int32_t <Name>;` + `#define <Name>_<值名> <序号>`。
4. 顶层基本类型 typedef（`typedef int64_t Q_RxLevMin;` 等）。
5. 别名 typedef（`typedef Y X;`，含 CONTAINING 别名）。
6. 顶层 `SEQUENCE OF` 包装结构体：
   ```c
   typedef struct PagingRecordList { PagingRecord* items; uint32_t count; } PagingRecordList;
   ```
7. 结构体定义（依赖拓扑序，`CONTAINING` 指针边不参与排序）：
   - `SEQUENCE`：根字段按 ASN.1 声明顺序；`OPTIONAL` → `bool has_<field>;` + 值字段；
     `DEFAULT` → 只生成值字段；`CONTAINING` → `<Target>* field;`（无 `has_`，NULL 表示未出现）；
   - 扩展组 `<Type>_ExtGroupN` 结构体（组内 `OPTIONAL` 仍有 `has_`）先于父结构体定义；
     父结构体中每组生成 `bool has_extGroupN; <Type>_ExtGroupN extGroupN;`；
   - 直接扩展添加项（不在 `[[ ]]` 中）按标准 PER 逐项生成
     `bool has_<field>; <Type> field;`（见 4.3 的说明）；
   - `CHOICE`：
     ```c
     typedef enum X_Tag { X_Tag_alt0 = 0, ... } X_Tag;
     typedef struct X { X_Tag tag; union { ... } u; } X;
     ```
     `tag` 数值即根备选索引（扩展备选接在根备选之后）；
   - 空 `SEQUENCE`：`uint8_t _dummy;`；`NULL` 类型映射为 `Null`。
8. 命名：方案第 3 章（N1–N10）。匿名结构类型名 = 父类型名 + `_` + 字段名首字母大写，
   若字段名与父类型名的最后一段重叠则合并（满足方案 3.2 两个示例）；
   `SEQUENCE OF` 匿名元素类型加 `_Item` 后缀；`SetupRelease { X }` → `SetupRelease_<X>`。
9. 字段名：ASN.1 原拼写，`-`→`_`；C/C++ 关键字追加 `_`；`has_` 前缀同上规则转义。
10. 注释：每个类型/字段带 ASN.1 原文、源行号、约束、presence；`CONTAINING` 字段额外
    标注内层类型与 NULL 语义。注释语言中文，Doxygen 风格。

### 2.2 `messages/rrc_messages.h`

```c
typedef enum MessageKind {
    MessageKind_MIB = 1,                       /* BCCH-BCH */
    ...                                         /* 1..53，方案附录 A 顺序 */
} MessageKind;

static inline ChannelType ChannelOfMessageKind(MessageKind kind);
```

`ChannelOfMessageKind` 用 `switch` 实现（纯 C99，无宏/模板）：非法 kind 返回 `(ChannelType)0`。
每个 MessageKind 注释包含：ASN.1 消息名、结构体名、信道、包装位。

### 2.3 `src/generated/codec_internal.h`

```cpp
#ifndef RRC_CODEC_GENERATED_CODEC_INTERNAL_H
#define RRC_CODEC_GENERATED_CODEC_INTERNAL_H

#include "rrc_codec/rrc_codec.h"     // 结构体 + MessageKind + ErrorCode
#include "../core/bitstream.hpp"      // rrc::v1810::Encoder/Decoder

namespace rrc {
namespace v1810 {

// 每个结构体类型与顶层 SEQUENCE OF 类型三件套；
// 函数只读/填充 value，不接管调用方指针所有权（解码分配用 std::malloc）。
ErrorCode Encode_<CName>(Encoder& enc, const <CName>& value);
ErrorCode Decode_<CName>(Decoder& dec, <CName>& value);   // 失败时内部已清理并清零
void      Free_<CName>(<CName>& value);                    // 递归释放，清零，可重复调用

// 仅对 CONTAINING 目标类型生成：
ErrorCode EncodeContained_<CName>(Encoder& enc, const <CName>& value);
ErrorCode DecodeContained_<CName>(Decoder& dec, <CName>*& out);

// 53 个消息入口；<KindSuffix> 为 MessageKind_ 之后的拼写：
ErrorCode EncodeMessage_<KindSuffix>(Encoder& enc, const <MsgType>& value);
ErrorCode DecodeMessage_<KindSuffix>(Decoder& dec, <MsgType>& value);
void      FreeMessage_<KindSuffix>(<MsgType>& value);

}  // namespace v1810
}  // namespace rrc

#endif
```

生成物分块：`src/generated/codec_partNNN.cpp`（每 ~150 个类型一个 TU，名字 `codec_part001.cpp`…），
每块 `#include "codec_internal.h"`。分块清单由生成器写入 `generated/Sources.cmake`：

```cmake
set(RRC_CODEC_GENERATED_SOURCES
  "${CMAKE_CURRENT_SOURCE_DIR}/src/generated/codec_part001.cpp"
  ...)
```

## 3. 手写核心（src/core）

| 文件 | 职责 | 负责人 |
|---|---|---|
| `bitstream.hpp` + `bitstream.cpp` | `BitWriter/BitReader/Encoder/Decoder`（PER 原语） | 运行时 |
| `error.cpp` | `GetLastErrorInfo`/`SetErrorHandler`/版本函数 + 线程局部错误 | core-api |
| `codec_api.cpp` | `EncodeMessage`/`FreeEncodedMessage`/`DecodeMessage`/`FreeMessage` | core-api |
| `dispatch.cpp` | 53 路 `switch(kind)` 分派到 `EncodeMessage_*`/`DecodeMessage_*`/`FreeMessage_*` | core-api |

`codec_api.cpp` 规则：

- 参数校验（kind 1–53、指针、`size <= RRC_CODEC_MAX_INPUT_BYTES`）；
- `encoded` 先清零；失败再次清零；
- 编码：`Encoder enc; rc = EncodeByKind(kind, message, encoded)`；成功后
  `malloc(enc.ByteLength())` 复制 `enc.Finish()`（补零后的字节），
  `size=字节数`、`bitLength=enc.BitLength()`；`malloc` 失败 → OutOfMemory；
- 解码：先 `ChannelOfMessageKind(kind)==channel` 校验（否则 ChannelMismatch）；
  `memset(message,0,sizeof)` 由分派/生成函数负责；失败后调用 `FreeByKind` 并清零；
- `EncodeByKind` 在 dispatch.cpp 中完成 `const void*` → 具体结构体指针的转换；
  成功返回 Ok，失败返回错误码（生成函数返回值）；
- 异常兜底：`try { ... } catch (std::bad_alloc&) { OutOfMemory } catch (...) { InternalError }`；
- 记录错误：`StoreLastError(code, channel, bitOffset)`；bitOffset 取自
  `enc.BitLength()` / `dec.BitOffset()`。

## 4. PER 语义（与方案 6.3/6.4/6.5 对应）

### 4.1 消息入口包装位

编码器先写固定选择位（约束整数索引），解码器读取并校验；映射见方案附录 A：

| 信道 | 包装路径（索引序列） | 位数 |
|---|---|---:|
| BCCH-BCH | message=0（mib） | 1 |
| BCCH-DL-SCH | message=0(c1), c1: systemInformation=0 / SIB1=1 | 2 |
| DL-CCCH | message=0(c1), c1: rrcReject=0 / rrcSetup=1 | 3 |
| MCCH-r17 / MulticastMCCH-r18 / PCCH | message=0(c1), c1 索引 0 | 2 |
| DL-DCCH | message=0(c1), c1 索引 0..12（4 bit） | 5 |
| UL-CCCH | message=0(c1), c1 索引 0..3（2 bit） | 3 |
| UL-CCCH1 | message=0(c1), c1 索引 0（3 bit 含 spare 2bit） | 3 |
| UL-DCCH（c1） | message=0(c1), c1 索引 0..15（4 bit） | 5 |
| UL-DCCH（c2） | message=1(messageClassExtension), messageClassExtension: c2=0, c2 索引 0..15（4 bit） | 6 |

包装层为 CHOICE；索引用 `WriteConstrainedInteger(index, 0, count-1)`。
解码时索引与期望不符：`NULL/SEQUENCE {}` 占位 → `UnsupportedMessage`；
其他实际消息 → `MessageKindMismatch`；索引越界 → `InvalidChoiceIndex`。

### 4.2 构造类型

- `SEQUENCE`：扩展位（可扩展时）→ 根 OPTIONAL/DEFAULT 位图（按声明顺序）→ 根字段 →
  扩展添加项（bitmap + open types）；
- `CHOICE`：扩展位 → 根索引（单备选 0 bit）→ 备选值；扩展备选 = 扩展位 1 +
  normally small non-negative 索引 + open type；
- EXT 添加项：`any = 任一存在`；`WriteBit(any)`；若 any：
  `WriteNormallySmallLength(addition_count)` → `addition_count` bit 位图 →
  每个存在项：open type（组 = 组内 SEQUENCE 内容；直接添加项 = 字段值本身）；
- `DEFAULT`：位图位 = `value != default`；值为默认时写 0 且不编码；解码位 0 填默认值；
- 空 SEQUENCE / NULL：0 bit；单值 ENUMERATED：0 bit；单备选 CHOICE：0 bit。

### 4.3 扩展添加项的唯一偏离（已论证）

方案 3.5.7 描述“直接添加项合并为一个 `<Type>_ExtAdditions` 子结构”。38.331 的可扩展
SEQUENCE 中直接添加项仅 `ul-SpecificParameters.bitRateQueryProhibitTimer`（1 个），
若按“组”编码会在开放类型内多写一个 OPTIONAL 位图位，与 X.691/现行 v1/pycrate 不一致。
因此实现按 **标准 PER**：每个直接添加项各自占 1 个位图位与 1 个 open type（内容为该字段值），
结构体中逐项生成 `bool has_<field>`。其余规则与方案一致。

### 4.4 CONTAINING

- 结构体表示为 `<Target>*`；编码：`EncodeContained_<Target>` 用临时 `Encoder` 编码内层、
  `Finish()` 后 `WriteOpenType`；解码：`ReadOpenType` → 子 `Decoder` → `Decode_<Target>` →
  `malloc` 挂指针；失败释放；深度计数由 `Encoder::PushContaining/Decoder::PushContaining`
  维护，超 `RRC_CODEC_MAX_CONTAINING_DEPTH` → `ContainingDepthExceeded`；
- 解码后校验子位流尾部：`CheckOpenTypeEnd()`。

### 4.5 变长类型

| 约束形态 | 长度编码 |
|---|---|
| 定长（lb==ub） | 不写长度 |
| 变长且 ub<65536 | 约束整数 `(n-lb)`，位宽 `ceil(log2(ub-lb+1))` |
| ub>=65536 或无 SIZE | 半约束长度：长度确定量（16K 分片形式），再写内容 |

SEQUENCE OF 的 ub>=65536 分片时按“分片长度 + 该分片元素”交错；生成代码用
`WriteFragmentHeader` / `WriteLengthDeterminant` / `ReadLengthDeterminant` 循环。
BIT/OCTET STRING 的半约束长度由运行时的 `WriteSemiConstrained*` / `ReadSemiConstrained*` 处理。

## 5. 所有权与内存

- 生成结构体中所有动态内存由 `std::malloc` 分配：
  `SEQUENCE OF` 数组、`BitString.bytes`、`OctetString.bytes`、`CONTAINING` 内层结构体；
- `Free_<Type>` 用 `std::free` 递归释放并 `memset` 清零；
- 解码函数入口把输出结构体 `memset(0)`；任何失败路径先 `Free_<Type>` 再清零返回；
- 编码只读，不做分配（临时开放类型缓冲除外）。
