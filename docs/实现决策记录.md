# v2 实现决策记录（ADR）

> 本文记录实现阶段对《RRC编解码库简化方案.md》(v0.5) 的具体落地决定与必要的
> 澄清/偏离，便于评审与后续维护。编号 ADR-0xx 与方案章节对应。

## ADR-001 复用 ASN.1 前端，替换发射器

- 复用 `tools/rrcgen/rrcgen/{lexer,parser,normalize,resolver,ir,names,ast,models,
  diagnostics,stats}.py`，仅新增 `cnames.py`、`cmodel.py`、`cli.py` 与
  `emitters/c_*.py`。
- 理由：前端已能对 v18.10.0 全量解析并通过原有 38 个测试；编解码语义由方案固定，
  风险集中在 C 发射器。
- 结果：`python -m rrcgen --check` 生成物逐字节可复现。

## ADR-002 C 命名规则（方案第 3 章）

- 顶层类型：ASN.1 原名，`-`→`_`，无前缀（N1）；匿名类型：父类型名 + `_` +
  字段名首字母大写（N2）。
- **重叠合并**：当字段名大写形式以父类型名最后一段为前缀时合并。例如
  `RRCReconfiguration` + `criticalExtensions` → `RRCReconfiguration_CriticalExtensions`，
  其备选 `criticalExtensionsFuture` → `RRCReconfiguration_CriticalExtensionsFuture`
  （同时满足方案 3.2 两个示例）。
- `SEQUENCE OF` 匿名元素类型追加 `_Item`；`SetupRelease { X }` →
  `SetupRelease_<X 的 C 名>`（参数用内层 setup 备选类型的 C 名，保证可复现）。
- 全局 C 标识符注册表按“命名类型 → SetupRelease 实例 → 匿名类型 → 扩展组结构”
  顺序注册，冲突追加 `_2`、`_3`…并写入 `generated/rrc_stats.json` 的
  `NameRenames`（实测 1 处：`PCI_Range` → `PCI_Range_2`）。

> **已知文字差异**：方案 3.2 补充示例写作
> `SIB1_UAC_BarringInfo_UAC_AccessCategory1_SelectionAssistanceInfo`（缩写 `UAC` 全大写），
> 与 N2“字段名首字母大写”规则以及方案 3.6.1 的 `MIB_Dmrs_TypeA_Position`（`Dmrs`
> 只大写首字母）互相冲突。实现遵循 N2 规则，得到
> `SIB1_Uac_BarringInfo_Uac_AccessCategory1_SelectionAssistanceInfo`。若采用缩写词表
> 会把 `DMRS`/`MRDC` 等大量既有方案示例改名，故不采用；如需逐字复现该示例，
> 应在方案层面统一命名规则后再改生成器。

## ADR-003 匿名 `SEQUENCE OF` 的两种表示

- 作为 **SEQUENCE 字段**：按方案 3.4 展开为 `<T>* items; uint32_t count;`，
  不生成额外类型。
- 作为 **CHOICE 备选 / SEQUENCE OF 元素**：union 成员/数组元素必须有完整类型，
  因此生成具名包装结构体（`<父类>_<字段>` 或 `<父类>_Item`）。这是 C 语言层面
  的必要补充，不改变 UPER 语义。

## ADR-004 直接扩展添加项：按标准 PER 逐项编码（对方案 3.5.7 的澄清）

方案 3.5.7 描述“`...` 之后不属于 `[[ ]]` 的添加项合并为一个 `<Type>_ExtAdditions`
子结构，整体对应一个开放类型”。X.691 中每个直接扩展添加项各自占一个扩展位图
位、各自一个开放类型（内容为字段值本身）。38.331 的可扩展 SEQUENCE 中直接添加项
仅 `ul-SpecificParameters.bitRateQueryProhibitTimer`（1 个，OPTIONAL）。

若按“组”编码会在开放类型内多写一个 OPTIONAL 位图位，与 pycrate/现行 v1 不一致。
因此实现采用标准 PER：直接添加项逐项生成 `bool has_<field>;`，编码时各占一位、
各写一个开放类型。这是本实现唯一偏离方案文字的地方，已在此记录。

## ADR-005 生成解码函数的失败清理

- 生成的 `Decode_<T>` 统一：
  1. 入口 `memset` 输出结构体；
  2. 函数体包在 `do { ... } while (false);` 中，失败用 `goto fail`；
  3. `fail:` 标签先 `Free_<T>` 再清零并返回 `dec.Error()`。
- 这样既保证 C++ 中 `goto` 不跨初始化，又保证任意失败路径无内存泄漏。

## ADR-006 错误粘滞 + 单次记录

- `Encoder`/`Decoder` 记录首个错误，后续原语为空操作；生成代码只在函数末尾
  返回 `enc.Error()` / `dec.Error()`。
- 公共 API 只在最外层写一次 `StoreLastError(code, channel, bitOffset)`。
- 首版不构造字段路径/错误字符串（方案 4.4）。

## ADR-007 测试样例构造器（测试期生成物）

- 为完成“53 个消息各至少 1 个样例”的门禁，生成 `tests/generated/message_samples.{h,cpp}`：
  为每个结构体生成 `BuildSample_<T>`，必填字段取约束下界/首个枚举值，必填
  `CONTAINING` 递归构造，`OPTIONAL` 留空（浅层 optional CONTAINING 填样例以覆盖
  开放类型解码）。
- 该生成物只服务测试，不安装、不属于公共 ABI；`tests/messages` 用它做
  “构造 → 编码 → 解码 → 再编码”比特一致性验证。
- 共享库构建时生成符号按方案隐藏（只导出 8 个 C ABI 函数），该测试跳过；静态库
  构建（默认）启用。

## ADR-008 共享库导出与运行时符号隐藏

- 公开头以 `RRC_CODEC_API` 标注 8 个函数；库目标 `CXX_VISIBILITY_PRESET hidden`，
  生成函数与内部 C++ 符号不导出。
- 实测 MinGW 共享库导出表恰为 8 个符号（`ErrorCode`/版本函数等其余内部符号隐藏）。
- `rrc_export.h` 在静态库消费时依赖 `RRC_CODEC_STATIC`；CMake `find_package`
  由 target 的 PUBLIC 定义自动传递，pkg-config 消费者由 `.pc` 的 Cflags 提供
  `-DRRC_CODEC_STATIC`。

## ADR-009 pkg-config 与可重定位安装

- `rrc_codec.pc` 的 `prefix` 由 `${pcfiledir}/../..` 反推，支持任意安装前缀；
- 静态库在 `Libs.private` 增加 `-lstdc++`（非 MSVC），Cflags 增加
  `-DRRC_CODEC_STATIC`；
- 本机（Windows/MinGW）未安装 pkg-config，该消费方式由 Linux CI 覆盖；CMake
  find_package 与 add_subdirectory 消费已在本机实测通过。

## ADR-010 生成物体积与分块（实测校准）

| 指标 | 方案估算 | 实测（v18.10.0） |
|---|---:|---:|
| `types/rrc_types.h` | 3–4 MB | 6.2 MB（5.9 MiB） |
| `src/generated/`（内部头 + 32 个 part） | 6–9 MB | 13.8 MB（13.2 MiB） |
| 静态库（Release，MinGW） | — | 8.34 MB |
| 共享库（Release，MinGW，未 strip） | ≤ 10 MB | 5.24 MB |
| 全量构建（8 并发，Release，含测试/示例） | ≤ 5 min | 8.7 s |
| 类型定义数（结构体/枚举/扩展组） | ~7,150 | 6,615 结构体+枚举 + 530 组 |
| 消息数 | 53 | 53 |
| 编解码分块 | ~30–40 | 32 |

超估算的主要原因是方案 3.7 要求的“每个字段/类型/生成函数详尽注释”（ASN.1 原文、约束、presence、源行号、编解码所有权）占用了大量体积；编译时间与共享库体积仍在门禁内。若后续需要压缩，可在
不改变 ABI 的前提下降级注释粒度或拆分类型头（方案 Q-10）。

## ADR-011 构建与安装

- 默认静态库；`RRC_CODEC_BUILD_SHARED=ON` 构建动态库并统一输出到 `build/bin`；
- CMake 包 `find_package(RrcCodec 2 CONFIG REQUIRED)`、pkg-config、
  `add_subdirectory` 三种消费方式均提供；
- 安装布局：`include/rrc_codec/`、`lib/`、`lib/cmake/RrcCodec/`、
  `lib/pkgconfig/rrc_codec.pc`、`share/doc/rrc_codec/`。
